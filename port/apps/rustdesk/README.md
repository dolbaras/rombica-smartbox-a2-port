# RustDesk для Rombica A2: аппаратное декодирование

Клиент RustDesk 1.4.9 для приставки (armeabi-v7a, Android 9). Изображение с удалённого компьютера
декодирует аппаратный декодер Amlogic, а кадр выводится прямо в текстуру Flutter: процессор не
декодирует и не копирует кадры.

Готовый APK: `out/rustdesk-1.4.9-a2hw-armeabi-v7a.apk`; для пользователей — в [Releases](https://github.com/dolbaras/rombica-smartbox-a2-roms/releases) репозитория rombica-smartbox-a2-roms.
Подписан ключом проекта (`../keys/rombica_apps.jks`), а не ключом разработчиков RustDesk.

Проверено 02.10.2026: подключение с приставки к Windows-ПК с монитором 2560×1080 по Wi-Fi,
H.264, 30 кадров/с. RustDesk на приставке занимает ~0,4–0,5 ядра. Кадры на экране совпадают с
полученными от ПК: приставка показывает каждый пришедший кадр, в очереди декодера 1–2 кадра.

## Зачем

Официальный RustDesk для Android декодирует H.264/H.265 **программно** (ffmpeg). Это видно по
исходникам 1.4.9:

- Android-версия собирается с `--features flutter,hwcodec` (`flutter/ndk_arm*.sh`), без
  `mediacodec`. `HwCodecConfig::get()` на Android заполняет только список кодировщиков
  (`ram_encode`), поэтому для декодирования берётся `CodecInfo::soft()`. Отметка «аппаратный
  кодек» в настройках относится к кодированию, когда телефон сам показывает свой экран.
- Число потоков программного декодера (`codec_thread_num`) ограничено половиной свободной
  памяти в гигабайтах, округлённой вниз. У приставки 1 ГБ ОЗУ, получается **один поток**. Одно
  ядро A53 декодирует 1080p лишь на единицы кадров в секунду: было 2–3 кадра/с.
- Модуль `mediacodec` в 1.4.9 заброшен и не компилируется. Android-часть выбрасывает все
  декодеры из списка кодеков, а до Android 10 не считает Amlogic аппаратным (список производителей
  жёсткий).

## Что изменено (`patches/`)

| Патч | Что делает |
|---|---|
| 0001 `scrap: hardware H.264/H.265 decoding with Android MediaCodec` | новый `libs/scrap/src/common/mediacodec.rs`: выбор аппаратного декодера; размер кадра из SPS опорного кадра; режим низкой задержки; вывод в Surface текстуры с отдельным потоком вывода (поток видео только подаёт кадры); без Surface — вывод в память и NV12→RGB через libyuv; ожидание первого кадра до 1 с; при зависании — ошибка и переход на программный декодер. В `codec.rs` MediaCodec пробуется раньше программного декодера; при «Авто» клиент просит у ПК H.264 |
| 0002 `android: hardware decoders and a texture for them` | `setCodecInfo()` передаёт декодеры, до Android 10 любой не программный декодер считается аппаратным; методы `create_video_texture`/`release_video_texture` (SurfaceTexture движка Flutter, его Surface уходит в Rust через `FFI.setVideoSurface`) |
| 0003 `flutter: show the hardware decoder's texture on mobile` | кадр в текстуре сообщается интерфейсу событием `EventToUI::Texture` (не чаще раза в секунду); мобильный экран показывает виджет `Texture` там, где рисовалась картинка; для холста, масштаба и мыши хранится нерисуемая картинка-заглушка размером с экран |
| 0004 `client: log video decode failures to logcat` | ошибки кадров и отказ от кодека — в logcat |
| 0005 `android: no software update check` | приложение не ищет обновления: официальное обновление заменило бы эту сборку; переключатель «Проверять обновления при запуске» скрыт |

События декодера пишутся в logcat с тегом `rustdesk-mc`: `adb logcat -s rustdesk-mc`. Файл
журнала RustDesk на Android обычно не создаётся.

## Поведение декодера Amlogic (OMX.amlogic.*, Android 9)

Найдено пробниками из `tools/` (см. ниже):

- вывод в память — только NV12 (формат 21) или «flexible», I420 (19) нет;
- настройка с размером 0×0: H.265 выделяет буферы 4096×2304 и даёт 13 кадров/с, поэтому размер
  берётся из SPS;
- в выводе в память формат всегда сообщает настроенный размер: больший поток уменьшается
  аппаратно, меньший кладётся в угол. Клиент рисует кадр строго размером с удалённый экран,
  поэтому декодер настраивается ровно на него;
- `vendor.low-latency.enable=1`: H.264 отдаёт каждый кадр сразу (задержка декодера ~18–35 мс).
  **H.265 придерживает последний кадр** до прихода следующего, флаг на него не действует — поэтому
  при выборе «Авто» клиент просит H.264;
- **кадр из нескольких слайсов** (например, x264 `sliced-threads`) останавливает декодер H.264
  после первого кадра. Защита: если больше 8 кадров дольше 1 с не выходят, сборка переходит на
  программный декодер;
- при выводе в текстуру декодер сначала выделяет буферы под кадры и отдаёт первый входной буфер
  позже 100 мс; клиент RustDesk отказывается от кодека, если не удался первый кадр, поэтому
  первый кадр ждётся до 1 с;
- предел вывода в память ~51 кадр/с при 1080p; вывод в текстуру — 30 кадров/с 2560×1080 без
  нагрузки на процессор.

## Установка на приставку

```bash
port/apps/rustdesk/install_on_box.sh            # adb подключён к приставке
```

Подпись другая, поэтому поверх официального RustDesk APK не встанет. Скрипт сохраняет данные
приложения (ID, пароль, адресная книга) в `/data/local/tmp/rd_backup.tgz`, удаляет приложение,
ставит APK и до первого запуска возвращает данные с новым владельцем и метками SELinux (нужен
root, есть в прошивке порта). Проверено: ID и ключ после переустановки те же.

Обновление этой же сборки: `adb install -r …` — данные сохраняются и без скрипта.
Вернуть официальный RustDesk — тем же скриптом с официальным APK: `install_on_box.sh <apk>`.

## Ограничения

- **Просадки при перетаскивании окон** — со стороны ПК, не приставки. RustDesk на ПК при скачке
  задержки сети резко снижает частоту кадров (до 1–4) и потом поднимает за ~10 с. По Wi-Fi 2,4 ГГц
  (AP6181) скачки задержки неизбежны (пинг 2–10 мс, при нагрузке до ~60 мс). Должны помочь
  (не проверялось) кабель Ethernet, качество «Оптимизировать время отклика», разрешение
  удалённого экрана 1920×1080.
- **Нагрев:** при работе 2560×1080 процессор ~80–85 °C с маленьким радиатором (порог снижения
  частоты — 80 °C).
- Текстура одна: при двух сеансах сразу второй декодирует в память (NV12→RGB на процессоре).
- Изменён только мобильный интерфейс Android; режим «текстуры» на настольных версиях не трогался.
- Проверено с одним ПК и одним кодировщиком (видеокарта ПК автора). Для кодировщиков, которые
  режут кадр на слайсы, сработает переход на программный декодер — медленнее, но работает.
- VP8, VP9 и AV1 по-прежнему программные (в чипе нет VP9, AV1 нет в Android 9).

## Armbian

На Armbian официальный клиент декодирует программно в один поток; аппаратный декодер
meson-vdec придерживает 2–3 кадра. Доработка отложена — см. `port/armbian/rustdesk/README.md`.

## Сборка

```bash
port/apps/rustdesk/build_rustdesk.sh
```

Скрипт повторяет CI RustDesk (версии из `.github/workflows/flutter-build.yml` тега 1.4.9): Flutter
3.24.5 с патчем из `.github/patches`, NDK r28c, vcpkg `120deac3…`, Rust 1.75, cargo-ndk 3.1.2,
flutter_rust_bridge_codegen 1.80.1. Исходники, инструменты и промежуточные файлы — вне проекта, в
`~/build/rombica-smartbox-a2/rustdesk` (переменная `RD_BUILD`, ~25 ГБ); Android SDK —
`~/build/rombica-smartbox-a2/android-sdk` (`ANDROID_SDK`).
Нужны пакеты apt: `clang libclang-dev llvm-dev nasm ninja-build cmake pkg-config libgtk-3-dev`.

Шаги: исходники и инструменты (если их нет) → патчи (`git apply`, уже наложенные пропускаются)
→ зависимости vcpkg (ffmpeg, libvpx, aom, opus…) → мост Flutter↔Rust → `librustdesk.so`
(`cargo ndk … --features flutter,hwcodec,mediacodec`) → APK, подписанный ключом проекта.
`key.properties` для Gradle пишется с экранированием `\uXXXX`: Java читает его в Latin-1, а путь
проекта содержит кириллицу.

## Пробники MediaCodec (`tools/`)

`tools/run_probe.sh` собирает и запускает на приставке через `app_process` (без установки
приложения):

- `McTest` — декодирование в память: форматы цвета, формат вывода, кадры/с, задержка, кадры в
  очереди, сохранение кадра (`dump=N`);
- `McSurf` — декодирование в SurfaceTexture, как кормится текстура Flutter, с чтением кадра
  обратно через OpenGL (проверка, что в текстуре настоящая картинка).

Параметры — в начале `McTest.java` и в `run_probe.sh`.
