# Rombica SmartBox A2 (Amlogic S905L2) — Android 9

**Русский · [English](#english)** · Готовые прошивки / Firmware: [rombica-smartbox-a2-roms](https://github.com/dolbaras/rombica-smartbox-a2-roms)

Порт **Android 9 (SlimBOX 9.20)** на приставку Rombica SmartBox A2 с SoC **Amlogic S905L2
(GXLX)** и памятью LPDDR3 в eMCP. Загрузчик (U-Boot), ядро Linux 4.9 с модулями и приложения
собраны из исходников. Закрытые бинарники SlimBOX и Amlogic не подменяются, но в части из них
исправлены отдельные байты или добавлен свой код — таблица частот CPU в BL30, библиотека ввода,
компоновщик экрана, systemcontrol, Settings и TvSettings (разделы 3 и 5). Каждую такую правку
делает скрипт при сборке, сверяя исходный файл и окружение правки.

Авторы: **Dolbaras**, при участии Claude (Anthropic). Версия **v1.3** (08.10.2026).

Две сборки из одного порта: **ATV** (SlimBOX 9.20 ATV, интерфейс Android TV) и **AOSP**
(SlimBOX 9.20 AOSP, обычный лаунчер). Загрузчик, ядро, драйверы и правки vendor у них общие.
Есть и Armbian на microSD с меню выбора системы при включении — [`port/armbian`](port/armbian/README.md).

- Готовые прошивки (Android ATV и AOSP, образы Armbian для microSD, RustDesk) — во вкладке
  Releases репозитория [rombica-smartbox-a2-roms](https://github.com/dolbaras/rombica-smartbox-a2-roms/releases);
  инструкция по установке — [`release/INSTALL.txt`](release/INSTALL.txt).
- Что вошло в версию — [`release/CHANGELOG.ru.txt`](release/CHANGELOG.ru.txt)
  ([English](release/CHANGELOG.txt)).
- В этом репозитории — исходники порта (`port/`): скрипты сборки, патчи, установщик для Linux.
  Образы, бэкапы и исходные прошивки SlimBOX/VPLT в него не входят.

Проверено на приставке после чистой установки:

| | |

| Экран | HDMI 1080p60, CVBS 576i; OSD без артефактов. Мониторы ПК (с v1.3): родное разрешение по EDID уже в загрузчике (проверено: 1280×1024 через переходник HDMI-VGA), VESA-режимы 640×480 … 2560×1440 в «Разрешении экрана» |

## 2. Установка

Подробно — [`release/INSTALL.txt`](release/INSTALL.txt). Коротко (Linux):

```bash
git clone https://github.com/dolbaras/rombica-smartbox-a2-port && cd rombica-smartbox-a2-port/port
unzip ~/Загрузки/rombica_a2_android9_atv_v1.3.zip    # из Releases; или ..._aosp_v1.3.zip
tools/install_firmware.sh rombica_a2_android9_atv_v1.3.img
# выдернуть питание, зажать reset в гнезде AV, вставить питание, держать 5–8 с
```

Вместо кнопки reset приставку можно перевести в режим прошивки из консоли U-Boot (UART, см.
раздел 10): остановить автозагрузку пробелом и ввести `update 60000` — U-Boot минуту ждёт ПК.

Установщик повторяет то, что делает Amlogic USB Burning Tool:
1. разметка eMMC по DTB образа (`disk_initial`);
2. запись всех разделов (приставка сверяет sha1 каждого);
3. загрузчик, сброс env, перезагрузка.

Если на приставке нет рабочего загрузчика (USB BootROM, `lsusb`: `1b8e:c003 GX-CHIP`), скрипт сам
загружает загрузчик из образа в ОЗУ и продолжает. Заводские ключи (MAC и т.п.) сохраняются.

Прошивка подходит только для платы **S905X_EMCP_V12 / шасси VPN0123** (см. раздел 7).

## 3. Наш загрузчик и стоковый

Загрузчик Amlogic GXL — это цепочка BL2 → BL30 → BL31 → BL33 (U-Boot), упакованная в FIP.

| | Стоковый VPLT (Android 7) | Наш (v1.0–v1.3) |
|---|---|---|
| BL2 (инициализация LPDDR3) | VPLT, 15.09.2017 | **тот же** (побайтно, проверяется при сборке) |
| BL30 (питание, сон, таблица частот CPU) | VPLT | **тот же**; с v1.2 в таблице частот ступень 667 МГц заменена на 1512 МГц / 1140 мВ (`bl30_dvfs.py`) |
| BL31 (ARM Trusted Firmware) | v1.0 822871a, 08.09.2017 | v1.0 53f813e, 22.05.2019 (из SlimBOX): старый не запускает вторичные ядра у 32-битного ядра |
| BL33 (U-Boot 2015.01) | бинарник VPLT, 07.12.2022 | собран из исходников Amlogic android-p (2019) для платы `gxl_p271_v1` |
| Сборка U-Boot | — | Linaro GCC 4.8 aarch64-none-elf (штатный для этих исходников), 0 предупреждений |
| Упаковка BL33 | LZ4C | LZ4C (свой упаковщик `aml_lz4c.py`) |
| Ядра, которые грузит | только 64-битные (Android 7, ядро 3.14) | 32-битное ядро 4.9 Android 9, system-as-root |
| Поддержка S905L2 в U-Boot | есть (своя сборка VPLT) | добавлена: VPU, VPP, SAR ADC, HDMI, фаза SD на порту B |
| microSD в U-Boot | работает | работает (фаза 3 для порта B на GXLX) |
| Имена DTB (`aml_dt`) | `gxl_p212_1g` | `gxl_p271_1g/2g`, а для обратной совместимости ещё `gxl_p212_1g` |
| Окружение (env) | Android 7 | как у SlimBOX: system-as-root, SELinux permissive, `otg_device=1`, `frac_rate_policy`, HDMI 444 8 бит |
| Кнопка reset | USB-режим прошивки | то же (`upgrade_key` → `update`) |
| Мониторы (HDMI) | нет | с v1.3: режим выбирается по EDID монитора, VESA-режимы до 2560×1440 (см. ниже) |
| Размер | 819 200 байт | 820 736 байт (v1.2), 822 784 (v1.3) |

Итог: собраны только те части, которые должны были измениться (BL33, а BL31 взят новее); в BL30
заменены 14 байт таблицы частот. Шифрование блоков FIP в `gxlimg` случайное, поэтому образ
загрузчика побайтно не воспроизводится; в релиз идёт ровно проверенный на приставке экземпляр.

**v1.2: меню загрузки с microSD.** В U-Boot включена команда `irkey` (`CONFIG_IR_REMOTE`; сама настраивает ИК-декодер на NEC — после
включения и после Android он не готов принимать кадры), а в
окружение по умолчанию — `bootcmd=run start_sd_menu; run storeboot`: если на карте есть
`s905_autoscript` (наш образ Armbian), он показывает картинку «Android | Armbian» и 10 секунд ждёт
пульт; без карты грузится Android, как раньше. Раз это окружение по умолчанию, меню переживает
сброс настроек и переустановку прошивки. Патч — `port/bootloader/patches/0002-gxl_p271_v1-boot-menu-from-the-microSD-card.patch`.
Всё, что зависит от конкретной платы — память, питание, частоты, — осталось родным.

**v1.3: мониторы.** Раньше U-Boot всегда выводил сохранённый `hdmimode` (по умолчанию 1080p60),
не спрашивая приёмник, а VESA-режимы (1280×1024 и т. п.) вообще отвергал — на мониторе 5:4 при
загрузке не было изображения. Теперь (патч `port/bootloader/patches/0003-hdmitx-PC-monitors-on-HDMI.patch`):
- `hdmitx sink_mode` (плата вызывает её после `hdmitx hpd`, перед `vout output`) читает EDID и,
  если приёмник не заявляет `outputmode` или режим быстрее его предела частоты (дескриптор range
  limits), выводит родной режим приёмника: первый detailed timing (у монитора), иначе заявленный
  VESA-режим того же размера и частоты, иначе предпочтительный режим ТВ. Меняется только
  окружение текущей загрузки (`outputmode` и `hdmimode`, их же получает ядро), выбор Android
  остаётся в сохранённом окружении;
- разбор EDID: VESA-режимы из established/standard timings, Established Timings III и detailed
  timings, range limits, родной режим (так же, как ядро с патчами 0011/0012);
- вывод: VESA-режимы и 2560×1080 (VIC 90) в списке режимов; RGB 8 бит для VESA и DVI-приёмников
  (старая проверка стояла после `break` и не выполнялась); режим DVI для приёмников без HDMI VSDB;
  полярность синхроимпульсов из режима; пресет HDMI PHY по частоте TMDS;
- окно OSD для VESA-режимов: положение, которое systemcontrol хранит для режима
  (`<mode>_x/_y/_w/_h`, по умолчанию весь экран), а логотип и меню загрузки 1920×1080 сохраняют
  в нём пропорции (на 1280×1024 — 1280×720 с полями сверху и снизу), а не растягиваются;
- таблицы таймингов, регистров энкодера и PLL исправлены по стандарту VESA DMT и сверены с ядром
  (`port/tools/check_vesa_tables.py`): у 800×600, 1024×768, 1280×960, 1360×768 были неверные
  частоты или размеры, у 2560×1080 и 2560×1440 — тайминги 1920×1200.

**Armbian и прочие Linux.** U-Boot 64-битный, BL2/BL30/BL31 те же, что и у всех GXL, так что
загрузку «своих» ядер (в том числе 64-битных) загрузчик не ограничивает. Armbian (ophub, сборка
S905L2) запускается с microSD через наш U-Boot, Android на eMMC при этом не трогается. Инструкция,
нужные правки (DTB для HDMI и Wi-Fi, звук) и текущее состояние — [`port/armbian/README.md`](port/armbian/README.md).

## 4. Ядро: что было не так и как исправлено

Ядро — Amlogic Android P 4.9.113 (дерево Khadas для VIM1/VIM2/VIM3). Оно того же поколения, что
ядро SlimBOX: из 5 766 опций конфигурации отличаются 15. Наши патчи — [`port/kernel/patches`](port/kernel/patches).

| Симптом | Причина | Исправление |
|---|---|---|
| С настоящим ID чипа: мусор на экране (RDMA OSD не запускается), видео не играет, падение деинтерлейсера | ID GXLX = 0x26 численно больше, чем у TXLX/AXG, и проверки «чип не старше X» уводят S905L2 в чужие ветки | S905L2 считается чипом семейства GXL, а `is_meson_gxlx_cpu()` и `cpu_after_eq(GXLX)` по-прежнему видят GXLX. Ветки, которые Amlogic написал специально для GXLX (DI, VPP, цвет), работают |
| Звук в 2 раза быстрее («бурундуки») | на GXLX новые n2/sdm аудио-PLL (MPLL) применяются только после бита защёлки в `SAR_ADC_REG12`, а без него выход остаётся на 248 МГц | драйвер MPLL ставит этот бит, как ядро Amlogic 3.14 |
| microSD: CRC-ошибки в режиме high speed | неверная фаза тактирования для SD HS на GXLX | фаза 3 (как у стокового U-Boot) |
| Курсор мыши иногда «смазан» в косую полосу | компоновщик Android пишет картинку курсора в слой OSD2 плотно (ширина × 4), а драйвер выравнивал шаг строки до 64 байт: курсор не кратной 16 точкам ширины (40×36) сдвигался на каждой строке | у слоя курсора шаг строки и канвы выравнивается до 8 байт (патч 0008) |
| После перезагрузки (из Armbian или recovery) Android иногда висит на логотипе: «emmc: error -110 whilst initialising MMC card» | правка Amlogic в `vsprintf` печатала вместо строки адрес, если строка лежала в диапазоне кода ядра; промежуток `_text`…`_stext` (≈1 МБ выравнивания) отдаётся под обычную память, и имя настройки выводов eMMC превращалось в «0xc013c6c8_all_pins» — линии данных eMMC не включались | правка убрана, `%s` печатает строку как в обычном ядре (патч 0009) |
| В RustDesk правая кнопка мыши работала как «Назад», режим «Назад» нельзя было переключить на лету | библиотека ввода SlimBOX переводит правую кнопку в «Назад» жёстко (см. раздел 5) | параметр `hid.right_button_back`: правая кнопка сообщается как `BTN_SIDE` («назад» мыши), переключается без перезагрузки (патч 0010) |
| Индикатор: один цвет, после сна всегда синий | драйвер `sysled` рассчитан на одноцветный диод | режим для двухцветного диода: `sysled:blue` и `sysled:red`, при «выкл.» вывод переводится во вход, состояние сохраняется при сне |
| Монитор 1280×1024 через переходник HDMI-VGA: «вход не поддерживается» (Android выбирал 1080p, монитор держит до 140 МГц), выбранный вручную 1280x1024p60hz тоже не показывался (82 Гц) | таблица частот VESA хранит выход PLL после делителей (так нужно G12A), а GXL задаёт PLL частотой VCO — режим не находился, PLL оставалась от прежнего режима; список режимов не учитывал предел частоты монитора (range limits) и VESA-режимы из EDID | на GXL/GXM частота умножается на делители, добавлены VCO 3960/4830 МГц; `disp_cap` отбрасывает режимы быстрее range limits и включает VESA-режимы монитора, родной помечается `*` (патч 0011) |
| VESA-режимы с ошибками: 1280×800 на 70 Гц, 1360×768 никогда не предлагался, неверная полярность синхроимпульсов | данные таблиц Amlogic: у 1280×800 тайминги reduced blanking при частоте обычного; 855000 вместо 85500 кГц; полярность «+/+» для всех режимов, кроме 640×480; 1280×960 искался не по тому биту Established Timings III | тайминги, регистры энкодера, частоты и PLL — по VESA DMT (сверяет `port/tools/check_vesa_tables.py`), полярность берётся из режима (патч 0012) |
| Ошибки сборки дерева Khadas без их плат | ссылки на драйверы MCU и расширителя GPIO Khadas | ссылки взяты под их опции конфигурации |

Проверено и отвергнуто: у S905L2 контроллер eMMC/SD работает в новой раскладке регистров (v3).
При старой раскладке (v2) калибровка eMMC HS200 зацикливается.

Модули: медиадекодеры (Amlogic `media_modules`), Mali utgard r8p0 и Wi-Fi `dhd` собираются из
исходников тем же тулчейном. Сборка воспроизводимая: из одних исходников получаются байт в байт
одинаковые boot.img и модули (время сборки ядра — дата последнего патча).

## 5. Что изменено в Android (разделы vendor и system)

Файлы — [`port/vendor/overlay`](port/vendor/overlay), применяет `port/vendor/apply_overlay.sh`;
новый код в закрытых бинарниках SlimBOX — [`port/vendor/native`](port/vendor/native) (сегмент с
компилированным C, см. `port/vendor/native/build.py`); правки системных приложений —
[`port/system`](port/system).

- **Мониторы (v1.3).** Решения принимают те, кому они принадлежат:
  - *ядро* (патчи 0011, 0012) отдаёт в `disp_cap` режимы, которые монитор заявляет и может
    показать, родной помечен `*`;
  - *systemcontrol* (`native/systemcontrol`): при автоматическом выборе родной VESA-режим
    монитора — сам режим, а цвет — RGB 8 бит, как у загрузчика и ядра (SlimBOX ставил первый
    подходящий из списка YCbCr 4:4:4 / 4:2:2 и переключал формат после загрузки; выбранный
    пользователем формат не трогается); позиция OSD для VESA-режимов хранится в своих ключах
    `ubootenv.var.<режим>_x/_y/_w/_h` (раньше для них бралось окно 1920×1080);
  - *droidlogic.jar* (`vendor/make_droidlogic_jar.py`, код в
    `vendor/droidlogic/.../RombicaDisplayMode.java`): `OutputModeManager` записывал имя режима в
    `persist.sys.display.resolution`, а Android (`LocalDisplayAdapter`) разбирает его как
    `<высота>p<частота>hz`; на «1280x1024p60hz» разбор падал, экран не настраивался и курсор
    стоял в углу — теперь туда пишется «1024p60hz». «Автоматический выбор наилучшего
    разрешения» (`getHighestMatchResolution`) падал на VESA-режимах в `disp_cap` и закрывал
    TvSettings — теперь он выбирает так же, как systemcontrol;
  - *hwcomposer* (`native/hwc`, `make_hwc_modes.py`): таблица режимов знает 16 VESA-режимов
    (640×480 … 2560×1600); размер интерфейса у монитора — его родной (не больше 1920×1200), а
    плотность пропорциональна ширине, поэтому элементы интерфейса того же размера, что на 1080p;
  - *TvSettings* (`system/make_tvsettings_vesa.py`): в «Разрешении экрана» к списку ТВ-режимов
    добавлены эти VESA-режимы, показываются те, что есть в `disp_cap`.
- **GPU:** Mali-450 MP2 умеет только OpenGL ES 2.0, а SlimBOX заявлял 3.2 и Android Extension
  Pack, и приложения, которым нужен OpenGL ES 3, ставились и не работали. Теперь
  `ro.opengles.version=131072` и AEP недоступен (`etc/permissions/rombica_gpu.xml`).
- **Свойства** правятся в тех файлах, где их задаёт SlimBOX (`vendor/edit_props.py`: значение
  меняется на месте, ключ должен встречаться ровно один раз): `/vendor/build.prop` —
  `vendor/vendor_build.prop.in`, `/system/build.prop` — `system/system_build.prop.in` (имя
  устройства, версия сборки, OpenGL ES, Bluetooth выключен). В `/vendor/default.prop`
  дописываются только новые свойства порта (`default.prop.append.in`: версия порта, adb по USB,
  режим удалённого рабочего стола).
- **«Оптимизация приложений» Amlogic выключена** (`ro.vendor.app.optimization=false`, штатный
  выключатель): служба `com.droidlogic.Optimization` каждые 50 мс опрашивала список процессов и
  верхнее окно и передавала их в systemcontrol (~4% ядра процессора постоянно в com.droidlogic,
  плюс system_server и systemcontrol), а `liboptimization.so` по списку
  `/vendor/package_config/config` (зашифрован сдвигом байтов на 1) для бенчмарков, тестов CTS и
  Netflix отключала тепловые зоны процессора, закрепляла частоты и режимы GPU.
- **Автозапуск SlimBOX** (`tv.autostart`, раздел product): его `BootReceiver` получает и
  `LOCKED_BOOT_COMPLETED` и сразу читал настройки из хранилища, которое ещё не разблокировано, —
  приложение падало при каждой загрузке. Теперь до разблокировки пользователя он ничего не делает
  (работу выполняет следующий за ней `BOOT_COMPLETED`; `port/system/make_autostart_locked_boot.py`).

- **Модули и микрокод видео** из нашей сборки. Каталог `/vendor/lib/modules` заменён целиком:
  драйверы Wi-Fi от других приставок из SlimBOX убраны.
- **Wi-Fi AP6181:** путь к прошивке `/vendor/etc/wifi/40181`. Драйвер `dhd.ko` загружает и
  выгружает Wi-Fi HAL SlimBOX (`libwifi-hal-common-ext`, он находит чип по SDIO id `a962`), а не
  init при старте, как в сборке SlimBOX для AP6212 и в нашей v1.0. При ранней загрузке HAL
  пропускал определение чипа, писал в драйвер испорченный путь к прошивке и падал при каждом
  выключении Wi-Fi (`strlen(NULL)` в `is_wifi_driver_loaded`): повторное включение не работало до
  перезагрузки, а иногда зависали настройки и всё, что обращается к Wi-Fi
  (`init.amlogic.wifi_buildin.rc`).
- **Пульт, режим мыши:** `/vendor/etc/remote.tab6` (читает служба SlimBOX `remotecfg6`) —
  раскладка нашего пульта из родного DTB плюс кнопка «мышь» (0x44), которой в родной раскладке
  нет. Драйвер пульта Amlogic переключает по ней режим: стрелки двигают курсор, OK — нажатие.
  Поля режима мыши ядро Khadas читает из DTB только для своего пульта, поэтому они здесь.
- **Bluetooth** убран (в AP6181 его нет): функции объявлены недоступными, пункт настроек заменён.
- **Индикатор:**
  - приложение `ru.rombica.indicator` (`port/apps/indicator`) и оверлей настроек TvSettings
    (`port/apps/tvsettings_overlay`);
  - выбор хранится в `persist.vendor.rombica.led.blue/red`: приложение задаёт свойство через
    systemcontrol Amlogic (`droidlogic.jar`, через него приложения меняют настройки устройства), а
    init превращает значение в триггер светодиода ядра (`etc/init/rombica_a2.rc`) — сразу и при
    каждой загрузке. Ни служб, ни опроса.
- **Мышь и клавиатура** (Настройки slimBOXtv → «Мышь и клавиатура», было «Мышь»):
  - *Курсор.* Компоновщик Amlogic (`hwcomposer.amlogic.so`) копировал картинку курсора в его слой
    только при смене размера, поэтому текстовый курсор «залипал», а «Крупный указатель» не
    выключался. Исправленная копия (`port/vendor/make_hwc_cursor.py`, 36 байт) копирует каждую
    новую картинку и перенастраивает слой только при смене размера: если перенастраивать слой
    при каждом движении, курсор мерцает.
  - *Режим удалённого рабочего стола* — спрятанный переключатель SlimBOX (`mouse_touch_input`,
    свойство `persist.vendor.mouse_touch_input` больше никто не читал), показан нашим оверлеем
    `mouse.xml`; применяется сразу. Включён: правая кнопка мыши — правый клик, клавиатура «как на
    ПК» (Win, Tab, PrintScreen получают коды, которые Android не перехватывает, Enter снова
    Enter, Home на клавиатуре не выкидывает на главный экран; RustDesk в режиме «Карта» передаёт
    клавиши по скан-коду, и Windows получает настоящие Win, Alt+Tab, PrintScreen). Выключен: как в
    SlimBOX, правая кнопка — «Назад».
  - *Правая кнопка.* Библиотека ввода SlimBOX `libinputflinger.so` переводит её в
    BUTTON_BACK (в `getButtonState` и во встроенной копии в `CursorInputMapper::sync`), поэтому
    ни одно приложение не получало правый клик. Исправлены два байта
    (`port/vendor/make_rclick_lib.py`), а «Назад» на правой кнопке теперь делает ядро: параметр
    `hid.right_button_back` (патч 0010, init переключает его по свойству) сообщает её как
    `BTN_SIDE`, которую Android штатно превращает в «Назад».
  - *Клавиатура.* Раскладку выбирает та же библиотека ввода (`EventHub::mapKey`): новый код
    (`port/vendor/native/inputflinger`) при включённом режиме меняет коды перечисленных клавиш у
    клавиатур с общей раскладкой `Generic.kl` (пульт не затрагивается); режим читается при каждом
    нажатии, устройства не переподключаются. Библиотека лежит в образе system на своём месте.
  - Отдельный тумблер для клавиатуры в этом экране сделать нельзя: экран мыши SlimBOX сохраняет
    только переключатели, которые знает его код.
- **Настройки телефона** («Расширенные настройки» SlimBOX): экран «Подключенные устройства» в
  Android 9 рассчитан на Bluetooth и без него вылетал. Settings сам решает, какие экраны есть,
  по функциям устройства (`SettingsActivity.doUpdateTilesList`): экран Bluetooth он уже убирал
  без Bluetooth, теперь и «Подключенные устройства» (`port/system/make_settings_nobt.py`).
- **Как правятся системные приложения SlimBOX** (Settings, TvSettings, Автозапуск): smali-правка
  dex, подпись SlimBOX сохраняется — для приложений системных разделов Android берёт сертификат,
  не пересчитывая хеши содержимого, но сверяет длину, поэтому файл сохраняет размер и раскладку
  (`port/system/apkpatch.py`): новый dex сжимается zopfli и ложится на место старого (SlimBOX
  сжимал свои dex плотнее, чем zlib -9). Сборка воспроизводима (smali в один поток).
- **Сведения о порте:** Настройки → Проект slimBOXtv → «Порт Rombica SmartBox A2» (экран
  `PortInfoActivity` приложения «Индикатор», оверлей `sbx_project.xml`): версия, ядро и
  `/vendor/etc/rombica_port/CHANGELOG(.ru).txt`. Пункты онлайн-патчей SlimBOX с этого экрана
  убраны — они для других приставок. Значков в списке приложений у «Индикатора» нет.
- **Кодеки:** из `media_codecs.xml` убран аппаратный VP9 (у S905L2 его нет, стоковая прошивка его
  тоже не объявляет).
- `init.amlogic.media.rc` не грузит модуль VP9, а `init.amlogic.tb_detect.rc` пустой: tb_detect —
  закрытый модуль под другое ядро.
- У трёх библиотек SlimBOX исправлены обрезанные SELinux-метки.
- Имя устройства, версия сборки с авторством (в `build.prop`, см. выше), пульт, adb по сети.

## 6. Сборка из исходников

Нужны: Linux x86_64, python3 с модулем lz4 (пакет `python3-lz4`), git, curl, rsync, make, gcc,
libssl-dev (для gxlimg), e2fsprogs (`debugfs`, `e2fsck`), `simg2img`/`img2simg`, zopfli (пакет
`zopfli`), Java; для приложений — Android SDK (build-tools 30.0.3, platform 28) и JDK
(`port/apps/build_apps.sh`). Остальные Python-модули (pyusb, fdt, pyamlboot) лежат в
`port/tools/pylib`.

Исходники и тулчейны скрипты скачивают сами по закреплённым версиям и сверяют контрольные суммы:
ядро и модули — `khadas/*`, U-Boot — `libre-computer-project/amlogic-bootloader-uboot-repo-bl33`,
упаковщик FIP — `repk/gxlimg`, Linaro GCC 6.3 (ядро) и 4.8 aarch64-none-elf (U-Boot), GNU Arm
Embedded 4.8 2013q4 (код в бинарниках SlimBOX, в `port/toolchains`), smali/baksmali 2.5.2.
Исходные прошивки в репозиторий не входят: SlimBOX 9.20 для S905X с AP6212
(`s905x_wifi_ap6212_atv_9_20.zip`, `..._aosp_9_20.zip`) и родная прошивка приставки
`VPLT-02.A7.AL202304041919` (из неё берутся BL2/BL30 и данные DTB).

```bash
mkdir -p /tmp/rombica_in && cd /tmp/rombica_in
unzip ".../slimbox/s905x_wifi_ap6212_atv_9_20.zip" s905x_wifi_ap6212_atv_9_20.img
7z x ".../stock rom/VPLT-02.A7.AL202304041919.7z"
cd ".../port"
./build.sh /tmp/rombica_in/s905x_wifi_ap6212_atv_9_20.img /tmp/rombica_in/VPLT-02.A7.AL202304041919.img \
           out/rombica_a2_android9_atv_v1.3.img        # для AOSP: ..._aosp_9_20.img → ..._aosp_v1.3.img
```

`build.sh` по шагам:
1. **Загрузчик:** `bootloader/build_uboot.sh` (U-Boot: закреплённый коммит + `bootloader/patches`,
   дерево проверяется на точное совпадение с патчами, как у ядра; каталог сборки
   `~/build/rombica-smartbox-a2/uboot`) → `bootloader/make_bootloader.sh`. Готовый
   проверенный загрузчик можно подставить через `BOOTLOADER=<файл>.img`, например
   `rombica_a2_bootloader_v1.3.img` из релиза (релиз собран с ним: упаковщик FIP шифрует со
   случайными данными, и два прохода сборки дают разные файлы; собранный заново из этих
   исходников загрузчик совпадает с выпущенным по BL2, BL30 и BL31 побайтно, а U-Boot — всем,
   кроме даты сборки). Версия загрузчика совпадает с версией порта (`port/VERSION`) и видна в UART:
   `U-Boot 2015.01-rombica-a2-v1.3`. (В истории разработки варианты загрузчика назывались
   буквами: G = v1.0/v1.1, H = v1.2.)
   Таблицу частот CPU в BL30 меняет `bootloader/bl30_dvfs.py` (переменная `CPU_DVFS`,
   `CPU_DVFS=stock` — оставить родную).
2. **Ядро:** `kernel/build_kernel.sh` сам скачивает исходники по закреплённым коммитам и тулчейн
   Linaro GCC 6.3 (MD5 сверяется), накладывает патчи и собирает ядро, модули и boot.img. Затем
   тем же ядром пересобирается recovery. Каталог сборки — `~/build/rombica-smartbox-a2/kernel`
   (переменная `KB`), так как в пути не должно быть пробелов.
3. **DTB:** `dts/make_p271_dtb.py`, из DTB SlimBOX p212 и данных родного DTB VPLT.
4. **Приложения:** `apps/build_apps.sh`; TvSettings.apk для оверлея извлекается из образа SlimBOX.
5. **Исправленные бинарники SlimBOX** (каждый шаг сверяет MD5 исходного файла и байты вокруг
   правки): `vendor/make_hwc_cursor.py` и `vendor/make_hwc_modes.py` + `vendor/native/hwc`
   (`hwcomposer.amlogic.so`: курсор, режимы мониторов), `vendor/native/systemcontrol`,
   `vendor/make_droidlogic_jar.py` (`droidlogic.jar`), `vendor/make_rclick_lib.py` +
   `vendor/native/inputflinger` (`libinputflinger.so`: правая кнопка, клавиатура «как на ПК»);
   системные приложения — `system/make_settings_nobt.py`, `system/make_tvsettings_vesa.py`,
   `system/make_autostart_locked_boot.py`; свойства — `vendor/edit_props.py`.
6. **vendor, system и product:** `vendor/apply_overlay.sh` (заменённые файлы сохраняют права и
   метки), затем упаковка `pack/repack_aml_image.py` (VERIFY пересчитываются).

RustDesk с аппаратным декодированием собирается отдельно, не входит в образ:
`port/apps/rustdesk/build_rustdesk.sh` (Flutter, NDK, vcpkg, Rust — см. `port/apps/rustdesk/README.md`).

## 9. Принципы разработки

**Без костылей — обязательное правило проекта** (оно же в `CLAUDE.md` для автоматизированной
работы). Каждое исправление делается в том компоненте, которому принадлежит поведение, и так, как
это технически правильно, даже если путь дольше:

- аппаратное поведение — в драйвере ядра; решения политики — в том демоне или библиотеке, который
  их принимает (systemcontrol, hwcomposer, inputflinger, NetworkManager…); статическая настройка —
  в сборке образа (файлы, оверлеи, конфигурация);
- **запрещено:** скрипты и службы, которые после факта переопределяют или «поправляют» решение
  другого компонента; циклы, которые следят за сбоем и чинят его; запись регистров из
  пользовательского пространства (`/dev/mem`) вместо исправления драйвера; bind-mount и правки на
  лету вместо того, чтобы положить файл в образ; повторное применение настройки при каждой
  загрузке, потому что не найдено правильное место;
- закрытые бинарники SlimBOX/Amlogic правятся скриптами с проверкой MD5 и байтов вокруг правки,
  каждая правка описана (что, зачем, где); крупные изменения — полноценным добавленным кодом, а не
  трюками;
- скрипты допустимы только для разовых действий без «владельца»: сборка образов, прошивка,
  инструменты разработчика.

**Обходные решения, которые ещё предстоит заменить** (ревизия 08.10.2026):

| Где | Сейчас (костыль) | Правильно |
|---|---|---|
| Armbian, YouTube | `yt-play`: ffmpeg декодирует, mpv только показывает, потому что mpv падает на meson-vdec | исправить аппаратный путь (ffmpeg/mpv и драйвер v4l2) |
| Armbian v1.2 (образы в релизе) | `s905l2-mpll-load` (регистр MPLL через `/dev/mem`), `wifi-watchdog` (переподключение Wi-Fi раз в 30 с), `rombica-led` (демон опроса диска) | в исходниках v1.3 заменены: биты MPLL выставляет U-Boot (`gxlx_mpll_load.patch`), NetworkManager с бесконечными попытками автоподключения, драйвер `leds-bicolor-gpio` и правило udev. Образ v1.3 на приставке ещё не проверен, поэтому в выпуске пока v1.2 |

**Заменены правильными решениями в v1.3** (было → стало):
- мониторы: скрипт `rombica_display.sh` (`vendor.ui_mode` до старта графики, цикл возврата режима,
  `wm density`) → выбор режима в systemcontrol, размер интерфейса и плотность в hwcomposer,

- клавиатура «как на ПК»: `rombica_input.sh` (bind-mount `Generic_pc.kl`, перепривязка usbhid) →
  раскладка в библиотеке ввода (`EventHub::mapKey`);
- правая кнопка мыши: bind-mount исправленной `libinputflinger.so` при `zygote-start` →
  библиотека в образе system;
- «Подключенные устройства»: `rombica_nobt_ui.sh` (`pm disable` при каждой загрузке) → решение
  Settings по функции Bluetooth;
- индикатор: демон `rombica_led.sh` (inotify, запись sysfs от root) → свойство через
  systemcontrol и триггеры светодиода ядра по свойству в init;
- U-Boot: вывод без учёта приёмника → режим по EDID (раздел 3);
- свойства устройства: копии значений SlimBOX в `/vendor/default.prop`, которые побеждали за счёт
  порядка загрузки файлов → значение меняется в том `build.prop`, где SlimBOX его задаёт.

## 10. Разработка и отладка

- **UART:** `port/tools/uart_capture.sh <log>` пишет консоль в файл (до 2 часов, потом
  перезапустить). С двусторонним адаптером (CH340, на Ubuntu отключить `brltty`, который
  забирает порт) команды пишутся прямо в `/dev/ttyUSB0`:
  - в Android — консоль `console:/ $` (например, `logcat -d -b crash`, когда сети нет);
  - в U-Boot — остановить автозагрузку пробелами с момента сброса (пауза 1 с), затем
    `run storeboot` (Android в обход меню карты), `update 60000` (режим прошивки), `store
    read/write` (разделы eMMC). Не грузить данные по адресу `0x5000000`: там BL31 (secmon).
  - `tools/uart_reboot_android.sh` — тёплая перезагрузка Android с запуском Android в обход меню;
    `tools/uart_cycle_armbian_android.sh` — круги Android → Armbian → тёплая перезагрузка → Android
    (так ловилась и проверялась ошибка eMMC -110, патч 0009).
- **adb:** по сети (порт 5555), `adb root` работает.
- **Проверить новое ядро, не трогая рабочее:** `CMDLINE_APPEND="rootfstype=ext4 skip_initramfs ro
  rootwait androidboot.rombica_kernel=new" kernel/build_kernel.sh … out`, затем
  `kernel/test_on_box.sh out`. Ядро пишется в раздел recovery, модули — в отдельный каталог
  vendor, и приставка перезагружается в него. Передёргивание питания возвращает обычную загрузку.
- **Перезаписать отдельные разделы:** `tools/flash_parts.sh <образ> boot vendor …` (приставка в
  USB-режиме по кнопке reset).
- **Тест кодеков и частоты звука:**
  - `tools/codectest/run_codectest.sh /sdcard/<папка с файлами>`;
  - `am start -n ru.rombica.codectest/.TestActivity --es audiorate 20`.
- **BootROM и загрузка в ОЗУ:** `tools/ram_boot.sh <bootloader.img>` — ничего не пишет в eMMC.
- **Запасной загрузчик на microSD:** `sdcard/prepare_sd.sh`, `sdcard/write_bootloader.sh` (в
  картридере ПК). BootROM проверяет SD после eMMC.

## 11. Известные ограничения

- **AC3 / E-AC3** на приставке не декодируются: у чипа нет лицензии Dolby, декодер Amlogic отдаёт
  тишину. Работают HDMI passthrough в ТВ или ресивер и плееры со своим декодером (Kodi, VLC).
- **VP9 выше 720p и AV1** недоступны: в чипе нет VP9, а в Android 9 нет декодера AV1. SmartTube
  сам берёт H.264, поэтому **YouTube — максимум 1080p** (1440p и 4K YouTube отдаёт только в VP9 и
  AV1). Свои файлы, Plex/Jellyfin, IPTV в HEVC идут аппаратно до 4K 10 бит. Для фильмов 23,976
  кадра/с включите в плеере переключение частоты экрана (в SmartTube — Auto frame rate).
- **Чересстрочное видео в обычных приложениях** выводится через GPU без аппаратного
  деинтерлейсера (`media.omx.display_mode=0`, как в SlimBOX). Деинтерлейсер работает на пути
  видеослоя (`display_mode=1`).
- **tb_detect** (автоопределение порядка полей) не используется: это закрытый модуль.
- **Wi-Fi AP6181** — один поток, 2,4 ГГц, 20 МГц: реально до ~3 МБ/с. Для 1080p этого хватает с
  запасом (поток SmartTube ~1,2 МБ/с), для 4K лучше Ethernet (до ~11 МБ/с). Не ставьте приставку вплотную
  к роутеру (при −5…−10 дБм приёмник перегружается и закачки встают). Скорость приёма заметно
  зависит от эфира: соседние перекрывающиеся каналы (например, 8 и 9 у двух точек mesh) и помехи
  на 2,4 ГГц бьют по этому модулю сильнее, чем по телефонам. Лучше закрепить канал 1, 6 или 11.
- **Ethernet и Wi-Fi вместе:** при подключённом кабеле прошивка отдаёт приоритет Ethernet и не
  подключается к Wi-Fi автоматически.
- **SELinux в режиме permissive**, как в SlimBOX: у образов SlimBOX битые метки.
- **ADB по сети открыт без подтверждения и с правами root**, как в SlimBOX: `service.adb.tcp.port=5555`
  (vendor), `ro.adb.secure=0`, `ro.secure=0` (system). Любое устройство в той же сети может
  подключиться к приставке. Не подключайте её к чужим и общественным сетям. Исправление
  (`ro.adb.secure=1`: подключение надо разрешить на экране) запланировано и требует проверки, что
  в ATV и AOSP есть окно подтверждения.
- **Мониторы:** режимы выводятся из таблицы драйвера (VESA DMT, 16 режимов от 640×480 до
  2560×1600 и 2560×1080 по CEA-861). Если родной режим монитора есть только в виде detailed
  timing с другими полями гашения (например, reduced blanking 1680×1050), выбирается режим того
  же размера и частоты из таблицы, когда монитор заявляет и его; иначе — лучший из заявленных.
  2560×1600 (348,5 МГц) требует HDMI 2.0 у приёмника. Интерфейс Android больше 1920×1200 не
  делается (масштабируется аппаратно). Цвет на мониторе — RGB 8 бит (при автоматическом выборе;
  DVI-монитор другого и не принимает); формат, выбранный вручную в «Цветовом режиме», сохраняется
  для режима, если монитор его заявляет.
- **Синий светодиод** индикатора на приставке автора механически сбит (сколота линза), режим
  проверен по состоянию вывода. Индикатор — два отдельных SMD-светодиода по бокам от трёх
  отверстий у края платы (красный и синий, «+» — анод); синий меняется на любой синий SMD того же
  типоразмера, драйвер в ядре управляет обоими цветами.
- **Нагрев:** с маленьким радиатором 14×14 мм на 1080p процессор ~73 °C на 1,512 ГГц (снижение
  частоты начинается с 80 °C). Радиатор побольше (25×25 мм) и вентиляция корпуса дают запас.
- **USB Burning Tool под Windows и карта прошивки** (`aml_sdc_burn`) не проверялись.
- **Режим удалённого рабочего стола:** Ctrl+Пробел Android всё равно перехватывает (переключение
  раскладки); пока режим включён, Tab и Win в самом Android не работают. В RustDesk/RuDesktop
  выбирайте режим клавиатуры «Карта».
- **Официальный RustDesk декодирует программно** любой кодек, включая H.264/H.265 (отметка
  «аппаратный кодек» у него относится к кодированию), и на 1 ГБ ОЗУ — в один поток: 2–3 кадра/с.
  Аппаратное декодирование — в нашей сборке RustDesk (`port/apps/rustdesk`). RuDesktop —
  закрытый форк старой ветки RustDesk (1.2), исходников нет, оферта запрещает модификацию; в его
  библиотеке нет вызовов MediaCodec NDK, так что он, скорее всего, тоже декодирует программно
  (замером не проверялось). Просадки при перетаскивании окон в нашей сборке создаёт
  RustDesk на ПК в ответ на скачки задержки Wi-Fi; кабель Ethernet должен их уменьшить
  (не проверялось).
- **Ошибки самого SlimBOX:** в сборке AOSP `slim.box.tv.customizer` падает при запуске своего
  приёмника событий (класса `IntentReceiver` нет в его коде). При загрузке `WiredAccessoryManager`
  пишет в журнал `NumberFormatException: "HDMI=1"`: services.jar SlimBOX знает только старый
  формат switch, а ядро отдаёт состояние в формате extcon. На звук это не влияет: о подключении
  HDMI-аудио Android узнаёт от droidlogic (`HDMI_AUDIO_PLUG`, state=1), выход HDMI объявлен в
  конфигурации аудио.

## 12. Откат на родную прошивку VPLT

- Загрузчик: `port/tools/restore_vplt_bootloader.sh` (из BootROM). Он пишет первые 2 МБ
  user/boot0/boot1 из бэкапа eMMC и проверяет запись чтением. Бэкап нужен свой (у автора —
  `backup/vplt_working_2026-09-29`, в репозиторий не входит; другой каталог — переменная
  `BACKUP`, файлы `emmc_first_876MB.img`, `mmcblk0boot0.img`, `mmcblk0boot1.img`).
- Система: полная прошивка `VPLT-02.A7…img` через USB Burning Tool (Windows) или те же команды
  `update partition …`.
- Заводские ключи (MAC `68:1d:ef:…`) переживают переразметку.

## 13. Если у вас похожая приставка

- **Бэкап.** Снимите полный бэкап eMMC (boot0, boot1, user хотя бы до system) и родной DTB.
- **ID чипа и тип памяти:**
  - ID: `/proc/cpuinfo` → Serial у S905L2 начинается с `26`;
  - память: строка BL2 в UART, например `LPDDR3 chl: Rank0+1`.
- **Свои BL2/BL30.** Если память или плата отличаются, берите BL2/BL30 из своего родного
  `bootloader.img` (`gxlimg -t fip -e bootloader.img out`) и собирайте загрузчик
  `make_bootloader.sh`.
- **DTB.** `make_p271_dtb.py` берёт из родного DTB пульт, Mali, кнопки и т.д., сверяйте со своим.
  Для S905L (не L2), S905X и S905W патчи ядра не нужны, но и не мешают: они срабатывают только на
  GXLX.
- **UART и путь в BootROM** должны быть готовы до экспериментов с загрузчиком.

Исходники GPL-компонентов: ядро — `khadas/linux` (коммит в `port/kernel/build_kernel.sh`) плюс
`port/kernel/patches`; U-Boot — `libre-computer-project/amlogic-bootloader-uboot-repo-bl33`
(коммит в `port/bootloader/build_uboot.sh`) плюс `port/bootloader/patches`; ядро Armbian —
`unifreq/linux-6.18.y` v6.18.51 (`port/armbian/build_modules.sh`) и патчи в `port/armbian`;
RustDesk (AGPL-3.0) — тег 1.4.9 плюс `port/apps/rustdesk/patches`.

## English

Sources of the **Android 9 (SlimBOX 9.20)** port to the **Rombica SmartBox A2** TV box (Amlogic
**S905L2 / GXLX**, board S905X_EMCP_V12, chassis VPN0123, 1 GB LPDDR3), and of an **Armbian**
image for microSD with a boot menu. The detailed documentation above is in Russian.

- **Firmware:** the Releases of [rombica-smartbox-a2-roms](https://github.com/dolbaras/rombica-smartbox-a2-roms/releases).
  Install notes: [`release/INSTALL.txt`](release/INSTALL.txt) (Russian). Changes:
  [`release/CHANGELOG.txt`](release/CHANGELOG.txt).
- **What is built from source:** U-Boot 2015.01 (pinned Amlogic tree + `port/bootloader/patches`:
  S905L2 support, microSD boot menu, PC monitors on HDMI, MPLL load bits), Linux 4.9 with modules
  (khadas trees + `port/kernel/patches`: GXLX clocks, microSD high speed, bi-colour LED, VESA modes,
  OSD cursor, right mouse button), the device tree and the port's own apps.
- **What is patched in SlimBOX's closed binaries:** every change is a script that checks the input
  MD5 and the bytes around the change: the BL30 CPU frequency table (up to 1.512 GHz), the
  hwcomposer (cursor, monitor modes), systemcontrol (display mode and colour for monitors),
  libinputflinger (right click, PC keyboard), droidlogic.jar, Settings, TvSettings and the
  Autostart app (the APKs keep SlimBOX's signature).
- **Install from Linux:** `port/tools/install_firmware.sh <image.img>`, the box connected with a
  USB A-A cable and started with the reset button (inside the AV jack) held. It repeats what the
  Amlogic USB Burning Tool does; every partition is checked by the box against its sha1.
- **Build:** `port/build.sh <SlimBOX 9.20 s905x_wifi_ap6212 image> <stock VPLT image> <out.img>`.
  Sources and toolchains are downloaded at pinned versions; the input firmwares are not part of
  this repository. See section 6 for the steps and the needed packages.
- **Development rule:** fixes go into the component that owns the behaviour (driver, daemon,
  library, build); no scripts that correct another component after the fact. The remaining
  workarounds are listed in section 9.
- **Known issue:** network ADB is open without authorisation and with root (as in SlimBOX); keep the
  box on a trusted network.
